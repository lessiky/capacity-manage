## 1. 项目概述

### 1.1 项目背景

随着企业 IT 系统规模持续增长，各业务系统所占用的资源（服务器、存储、数据库、中间件等）不断攀升，容量管理面临以下问题：

1. **数据分散**：容量数据分散在各业务数据库、日志文件及既有监控系统中，无统一归集入口；
2. **口径不统一**：各系统对容量指标的定义与阈值（如磁盘使用率、DB 表空间、连接数）口径不一致，缺少基线、预警线、危险线的分级标准；
3. **人工成本高**：容量检查依赖人工执行 SQL、翻查日志，时效性差、易遗漏；
4. **响应被动**：容量瓶颈往往在影响业务后才被发现，缺乏事前预警与容量预测能力，扩容决策缺少数据支撑。

为此，建设**容量管理平台**（以下简称"本平台"），对容量数据实行"指标定义 → 数据采集 → 数据落地 → 监控预警 → 报表分析"的全流程集中管理。

### 1.2 建设目标

| # | 目标 | 说明 |
| --- | --- | --- |
| 1 | 业务系统统一管理 | 统一登记业务系统档案（部门、负责人、级别、状态），作为容量管理的基本单元 |
| 2 | 指标与阈值标准化 | 统一容量指标定义，支持基线、预警线、危险线三级阈值管理与调整留痕 |
| 3 | 数据采集自动化 | 可配置采集流程，支持从数据库、日志文件等数据源采集并清洗转换；支持自定义 Python 脚本扩展采集与清洗 |
| 4 | 数据每日落地 | 指标数据按日落地归档，形成历史容量数据资产，支撑趋势分析与报表 |
| 5 | 监控预警主动化 | 实时/准实时监控，超线自动分级告警，告警闭环处理与 SLA 统计 |
| 6 | 分析决策数据化 | 多维容量报表、容量趋势与预测，辅助容量规划与扩容决策 |
| 7 | 交易日适配 | 内置交易日日历，采集调度与模板变量支持交易日语义（前一交易日等），契合证券业务节奏 |
| 8 | AI 辅助 | AI 一键生成采集流程与清洗脚本，AI 辅助容量预测，降低配置与分析门槛 |

### 1.3 建设范围

**范围内（一期）**

- 业务系统管理
- 容量指标管理（指标定义 + 基线/预警线/危险线阈值）
- 容量数据采集（数据库、日志文件两类数据源；SQL、日志解析、自定义 Python 脚本三类采集方式；数据清洗；调度执行）
- 交易日管理（交易日日历维护、前一交易日等变量、交易日调度）
- 每日容量指标数据落地（日内数据 + 每日汇总 + 历史归档）
- 容量报表（日报、趋势、使用分析、导出）
- 容量监控与告警（阈值判定、平台内告警展示与处理；对外通知推送为二期）
- AI 辅助能力（AI 一键生成采集流程与清洗脚本；AI 辅助容量预测）
- 基础系统管理（用户、角色、权限、日志）

**范围外（远期预留）**

- 容量扩容动作的自动执行（本平台只输出预警与扩容建议，不执行变更）
- 成本核算与计费
- 多租户 SaaS 化
- 与 CMDB/ITSM 深度集成（一期仅预留接口）

### 1.4 术语定义

| 术语 | 定义 |
| --- | --- |
| 业务系统 | 企业内一个独立的业务系统，是容量管理的基本归属单元（如订单系统、支付系统） |
| 容量指标 | 反映系统资源占用或容量状态的量化指标（如磁盘使用率、DB 表空间使用率、连接数） |
| 容量基线 | 指标的标称值/基准容量（如总容量、规划容量、100% 基准），用于计算水位 |
| 预警线 | 预警阈值，超过表示容量趋紧，需关注并安排计划性处理 |
| 危险线 | 危险阈值，超过表示容量风险 imminent，需紧急处置 |
| 水位 | 指标当前值相对基线（或阈值）的占用比例 |
| 采集流程 | 绑定"数据源 + 采集方式 + 清洗规则 + 目标指标 + 执行频率"的可配置采集单元 |
| 交易日 | 证券市场开放交易的业务日；平台维护交易日日历，采集调度与业务日期推导以其为准 |
| 前一交易日 | 当前业务日期之前最近的一个交易日（跳过周末与法定节假日），以系统变量 ${prev_trading_day} 表示 |
| 数据落地 | 采集得到的指标数据按规范清洗后持久化存入平台库（日内数据 + 每日汇总） |
| 容量预测 | 基于历史数据趋势外推，输出指标预计到达预警线/危险线的时间 |

### 1.5 设计原则

- **配置化驱动**：数据源、采集流程、清洗规则、阈值、报表模板均可配置，无需改代码；
- **数据标准化**：统一指标口径、单位与统计方式，做到"一个指标一个口径"；
- **松耦合可扩展**：数据源适配器、通知渠道、报表类型均可插拔扩展；
- **安全可审计**：凭据加密存储、权限分级、关键操作留痕可审计。

## 3. 总体业务设计

### 3.1 业务架构（分层）

```
┌─────────────────────────────────────────────────────────┐
│  展示层：Web 管理端 / 监控大盘 / 报表中心 / 通知推送（邮件、IM、短信） │
├─────────────────────────────────────────────────────────┤
│  服务层：指标服务 / 阈值判定与告警服务 / 报表服务 / 预测服务 / AI 辅助服务 / 调度服务（交易日感知） │
├─────────────────────────────────────────────────────────┤
│  数据层：日内数据 / 每日落地数据 / 历史归档 / 数据质量 / 告警记录 / 交易日日历 │
├─────────────────────────────────────────────────────────┤
│  采集层：数据源管理 / 采集流程（SQL / 日志解析 / Python 脚本）/ 清洗引擎（含脚本）/ 调度重试 │
├─────────────────────────────────────────────────────────┤
│  数据源层：业务数据库 / 日志文件（本地/SFTP）/（预留：API、监控系统）  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 核心业务流程

**流程一：容量指标上线流程**

```
系统建档 → 定义容量指标（归属系统、单位、统计方式）
        → 设置基线/预警线/危险线
        → 选择数据源，配置采集方式（SQL 模板 / 日志解析 / Python 脚本，支持 AI 一键生成）
        → 配置清洗规则（支持 AI 生成清洗脚本）与执行频率（支持交易日模式）
        → 数据预览校验（试跑）
        → 流程生效，开始定时采集
```

**流程二：每日数据处理流程（核心主流程）**

```
定时调度触发（分/时/日，支持交易日模式；变量支持 ${prev_trading_day}）
  → 执行采集（DB 查询 / 日志文件解析 / Python 脚本）
  → 数据清洗与校验（类型转换、单位换算、异常标记、去重）
  → 日内数据点落库
  → 超阈值实时判定 → 超线则生成/合并告警 → 分级通知
  → 每日定时（默认 00:10）对前一日数据做日汇总（max/min/avg/last）落地
  → 更新监控大盘、日报数据
  → 完整性检查，缺数标记并提示补采
```

**流程三：告警处理闭环流程**

```
告警生成 → 分级通知（值班/负责人/管理者）
  → 认领响应（SLA 计时）
  → 处理（填写处理措施）
  → 关闭（验证恢复，填写处理结果）
  → 归档统计（MTTA/MTTR、高频告警分析）
  ※ 超时未处理 → 自动升级通知上级/业务负责人
```

**流程四：报表生成与推送流程**

```
定时（日/周/月）或手工触发
  → 按报表模板取数（范围、分组、排序）
  → 生成报表（数据明细 + 图表 + 超线清单 + 预测列）
  → 在线查看 / 导出 Excel、PDF
  → 按订阅配置推送（邮件/IM）
```

### 3.3 关键业务规则

1. 一个业务系统可包含多个容量指标；一个指标唯一归属一个业务系统；
2. 阈值判定优先级：当前值 ≥ 危险线 → 危险级；否则 ≥ 预警线 → 预警级；
3. 同一指标同一级别在恢复前只保留一条活动告警（合并防抖），新数据刷新告警记录；
4. 每日落地后的数据不可直接修改，只能通过"手工修正"流程更正，修正需填写原因并保留原值与审计记录；
5. 历史数据默认保留 3 年（可配置），超期数据自动归档；
6. 系统下线时：停止其采集流程、冻结告警，历史数据保留；
7. 采集失败/缺数不影响其他指标采集（流程级隔离）。
8. 调度支持"自然日"与"交易日"两种模式；交易日模式下任务仅在交易日执行（或在交易日收市后窗口执行）。
9. 采集模板与日志文件命名支持系统变量：${biz_date}（业务日期）、${prev_trading_day}（前一交易日）、${next_trading_day}（后一交易日）、${trading_day_offset:N}（N 可为负，业务日期前/后第 N 个交易日）、${system_code}、${hour}。 日期变量支持 `:format` 后缀自定义输出格式（如 `${prev_trading_day:YYYYMMDD}`，支持 `YYYYMMDD`、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMM` 等）。

| 编号 | 功能点 | 需求描述 | 优先级 |

| FR-MET-12 | 阈值调整 | 支持在线调整阈值并即时生效（作用于下一次判定）；每次调整自动记录调整历史（操作人、时间、旧值→新值、原因，原因选填） | P0 |
| FR-MET-13 | 阈值模板 | 支持按模板批量设置阈值（如核心系统：预警 80%/危险 90%；一般系统：预警 75%/危险 85%）；新建指标时可选模板填充 | P1 |
| FR-MET-14 | 阈值视图 | 指标详情页展示：当前值、水位、基线、预警线、危险线（趋势图上以参考线叠加）及阈值调整历史 | P0 |
| FR-MET-15 | 阈值合理性校验 | 设置时校验：百分比型 0<预警线<危险线≤100（越高越差方向）；绝对值型按判定方向校验大小关系；不合法不允许保存 | P0 |

| 编号 | 功能点 | 需求描述 | 优先级 |

## 7. 非功能性需求

### 7.1 性能

| 项 | 要求 |
| --- | --- |
| 并发用户 | 支持 ≥20 并发在线用户，常规操作响应 <3s |
| 大盘/列表 | 总览大盘、列表类页面首屏加载 <3s（95 分位） |
| 采集规模（设计上限） | ≥500 个业务系统、≥5 万个容量指标 |
| 调度时效 | 日级采集任务全部在 30 分钟内执行完成；单流程执行超时上限 5 分钟（可配置） |
| 数据量 | 日数据增量 ≥1 万行/日，在线保留 3 年（≈1000 万行级）查询性能不显著劣化 |
| 报表生成 | 单份日报（全量指标）生成 <60s |

### 7.2 可用性

- 平台可用性 ≥99.9%（月度）；
- 调度任务失败自动重试，服务重启后自动恢复未完成任务；
- 数据库每日自动备份，支持按日恢复；
- 单数据源故障不影响其他数据源与流程（故障隔离）。

### 7.3 安全

- 数据源凭据加密存储（AES-256 或同等强度），页面/日志/导出全程脱敏；
- 传输层 TLS；会话超时自动登出；登录失败锁定策略；
- RBAC 功能权限 + 按系统的数据权限；关键操作（阈值、修正、权限、导出）全量审计；
- AI 辅助：提供给模型的数据样例须脱敏，AI 调用记录可审计（见 FR-AI-04）；
- 采集数据库账号仅授予只读权限；
- 平台自身纳入运维监控（进程、接口、磁盘）。

### 7.4 可扩展性

- 数据源类型、采集方式、清洗规则、通知渠道均为可插拔/可配置扩展点；
- 指标-阈值模型预留多维阈值扩展（如分时段阈值、多基线）；
- 报表与大盘组件化，便于新增报表类型。
- AI 能力可插拔：模型服务可切换行内/云端；AI 服务不可用时自动降级为纯手工配置，不影响主流程。

### 7.5 可维护性

- 阈值、流程、模板等配置变更热生效，无需重启服务；
- 完整运行日志与平台自检视图（FR-ADM-08）；
- 提供数据字典与配置导出，便于迁移与审计。

## 9. 风险与假设

### 9.1 风险与应对

| # | 风险 | 影响 | 应对措施 |

| 8 | AI 服务可用性与数据安全合规 | 功能降级/合规风险 | 行内或经授权模型服务优先；样例脱敏；调用审计；不可用时降级手工配置 |

### 10.3 采集流程配置示例

**数据库采集示例**

- SQL 模板：`SELECT usage_rate FROM sys_disk_info WHERE host = '${host}' AND ds = '${biz_date}'`
- 变量：`${host}`=10.1.1.10，`${biz_date}`=采集日期
- 结果映射：列 `usage_rate` → 指标值；单位 %；日内统计方式：最新值
- 清洗：数值保留 2 位小数；>100 标记异常
- 频率：每小时整点

**日志采集示例**

- 文件：`/data/logs/capacity/cap_${biz_date}.log`（SFTP 远程）
- 解析模式：正则 `\[CAP\]\s+metric=(\w+)\s+value=([\d.]+)\s+unit=(\w+)`
- 字段映射：group2 → 指标值，group3 → 单位；按指标名路由到对应指标
- 清洗：单位自动换算为指标单位；空行跳过
- 频率：每日 00:30（采集前一日日志）

**Python 脚本采集示例**

- 脚本：collect_cap.py（版本 v1.2，当前生效版本）；入参：${prev_trading_day}
- 逻辑：读取 SFTP 日志文件 cap_${prev_trading_day}.log，按指标汇总当日增量，输出 JSON：[{"metric": "log_growth", "value": 12.5, "unit": "GB"}]
- 清洗脚本：clean_cap.py，输入上述 JSON，按指标单位做单位换算（如 GB→TB）并保留 2 位小数
- 频率：交易日 17:30（交易日模式，收市后窗口）
- 沙箱：禁止网络访问、禁止本地写文件、执行超时 5 分钟

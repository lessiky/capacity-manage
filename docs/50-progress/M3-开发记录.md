## 2. 本阶段发现并修复的缺陷

| # | 缺陷 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | `RunDailySummary` 调用 `SummarizeDay(ctx, bizDate, nil)` 传入 nil 水位回调, 汇总遇有数据的指标即 panic（FR-DAY-08 水位从未落地） | 日数据水位恒空, 大盘/报表水位不可用 | 日汇总注入判定引擎（judge）计算水位与级别；SummaryFunc 签名扩展 params+calendar |
| 2 | `sum` 统计方式日汇总用 avg 近似（M2 遗留注释"精确实现见 5-1"） | sum 指标统计值失真 | 聚合 SQL 增加 `sum(clean_value)` 精确落地 |
| 3 | `/alerts/stats` MTTA/MTTR 使用 PG 专有 EXTRACT SQL 且无达成率, 与契约不符 | 统计不可移植、SLA 达成率缺失 | 预取告警行后 Go 内纯函数计算（`ComputeSLA`），按级别输出目标/实际/达成率 |
| 4 | 告警列表/导出未做数据权限过滤（契约 §11 要求导出受数据权限约束） | 越权可见 | 非平台管理员按 sys_data_scope（用户直授 + 角色生效）过滤 system_code |
| 5 | `alert_record.detail` jsonb 列插入 Go 零值空串 `''`，PG 报 22P02（M2 潜伏缺陷: 单测走 sqlite 不校验 jsonb, dev 环境阈值告警首次真实落库才暴露; M2 的 P2 告警 detail 均非空故未触发） | 阈值/缺数告警在真实 PG 上创建恒失败, 告警闭环整体不可用 | `Detail` 改 `*string`（零值落 NULL）; 同步排查全部 jsonb 字段 |
| 6 | 同类: `metric_value_day.original_snapshot` jsonb 零值空串插入 22P02 | 日汇总在真实 PG 上恒失败, 日数据/水位无法落地 | `OriginalSnapshot` 改 `*string`; 其余 jsonb 字段逐一核对（config/collect_config 必填, clean_config 有默认值, rules_applied 由引擎写合法 JSON, 均安全） |
| 7 | `/alerts/stats` 匿名结构体缺 json tag, 响应键为 `Level`/`MetricCode`（大写）, 与契约/前端 `level`/`metricCode` 不符 | 统计页签/统计条无法渲染 | 补 json tag |
| 8 | 告警终态（closed）后再认领/关闭返回 500（业务错误未映射状态码） | 前端无法按 409 提示处理 | handler 前置终态校验, 返回 40900 |
| 9 | 测试基建 flake: testutil 内存库名用 `UnixNano` 生成, 同一时钟节拍内两个 harness 同名（sqlite cache=shared 下同名=同库）→ 重复 seed 触发 UNIQUE 冲突（全量跑偶发, 跨午夜时段命中一次） | 单测偶发失败, 误报 | 库名追加原子自增序号, 保证唯一 |

# A5 后台请求数容量指标采集方案

> 需求: 采集 A5 交易系统 10 台服务器 `/data/aboss/log/{交易日}/*run_*{交易日}.txt` 中
> "业务统计" 段落(功能号,次数,总用时,最快,最慢,平均,名称), 按功能号前缀归并为
> **交易请求/非交易请求** 两类, 统计调用笔数、平均耗时(按调用次数加权)、最大耗时,
> 落库到既有指标树 **`A5_HOUTAI_QINGQIU`(后台请求数)**, 参与监控预警与报表。
>
> 关键约束: 指标口径**复用既有指标树**, 不新增指标层级; 10 台服务器的日志归入
> 数据源分类 **`A5-后台`**(`TEST_SYS01/后台`), 该分类下所有文件共用同一处理逻辑。

## 1. 指标口径(平台既有)

```
A5_HOUTAI_QINGQIU  后台请求数            aggregate (TEST_SYS01/A5)
├── A5_JIAOYIQINGQIU     后台交易请求      group
│   ├── A5_JIAOYIQINGQIU_BS   笔数      count/笔/sum
│   ├── A5_JIAOYIQINGQIU_AVG  平均耗时  avg/秒/avg    weightMetricCode=A5_JIAOYIQINGQIU_BS
│   └── A5_JIAOYIQINGQIU_MAX  最大耗时  max/秒/max
└── A5_FEIJIAOYIQINGQIU  后台非交易请求    group
    ├── A5_FEIJIAOYIQINGQIU_BS / _AVG(weighted) / _MAX
```

采集侧只需写 6 个叶子指标, 分组/汇总值由平台 `metricagg` 按 `weightMetricCode` 自动计算
(汇总平均 = Σ(值×笔数)/Σ笔数), 与展示、日汇总、阈值判定同一口径。

## 2. 日志格式

样例: `docs/a5_ss_fos_zx_41_run_20261016.txt`(**GBK 编码**), 服务停机/启动时输出业务统计段落:

```
20261016 22:01:06.326 业务统计 a5glht 20261015 21:07:27.140 - 20261016 22:01:06.326 (单位:毫秒).
20261016 22:01:06.334 功能号,次数,总用时,最快,最慢,平均,名称
20261016 22:01:06.339 S01703 2, 68.49, 4.55, 63.93, 34.24, 转融通清算文件浏览 source=[],rule=[]
...
20261016 22:01:06.591 33个服务被调用.
```

* 目录/文件名含**交易日**(如 `/data/aboss/log/20261019/a5_*_zx_41_run_20261019.txt`), 每台服务器目录下多个 `*run_*.txt`(每个服务一个), 需**合并全部文件**再按要求过滤聚合;
* 行内 `平均` 为两位小数舍入值, **精确加权平均必须用 `Σ总用时/Σ次数`**(总用时未舍入);
* 功能号形态**不固定**, 实测同一批日志中存在:
  * 字母码: `S01703`(清算服务)、`A00001`、`G00005`(两融)、`J00017`(期权)、`H00081`(基金)
  * 纯数字码: `310005`(普通股票买委托)、`667721`(盘口行情查询)
  * 字母数字混合码: `DT01SHZ1001`(上海Z1买入委托)、`DT01SZZ6001`(深圳创转债买入) ← **委托类功能号**
  * 脱敏码: `DT06****001`

  → 行正则的功能号分组取**第 3 个非空字段** `(?P<func>\S+)`, 不可限定 `[A-Za-z]+\d+`(会漏掉混合码/数字码/脱敏码)。

## 3. 复用平台既有能力

| 环节 | 平台能力 | 说明 |
| --- | --- | --- |
| 远程取件 | SFTP 日志数据源 (`datasource/sftp.go`) | 密码 AES-256-GCM 加密存储, 健康巡检 |
| 交易日变量 | `${biz_date:YYYYMMDD}` (`flow/variables.go`) | 按执行时刻推导目录/文件名 |
| 采集调度 | `scheduleMode=trading_day` + `windowTime=22:30` (`scheduler.go`) | 仅交易日 22:30 触发(业务统计约 22:01 落盘) |
| 分类采集 | 流程绑定 `dataSourceCategoryId` (`flow/engine.go`) | 分类下全部未停用日志数据源共用同一采集/清洗逻辑 |
| 段落聚合 | `logparse` 的 `mode=section` (`flow/collectors.go`) | 起止标记间逐行解析 → 前缀过滤 → 聚合 |
| 数据落地 | 采集→清洗→`metric_value_rt`→日汇总 (`flow/engine.go`, `data/store.go`) | 幂等 upsert, 失败重试 3 次 |
| 汇总/预警 | 指标树 `aggregate/group/normal` + `weightMetricCode` (`metricagg`) | 汇总平均自动按笔数加权 |

## 4. 数据源分类 `A5-后台`

10 台服务器(`128.6.120.32/33/34/38/39/40/41/42/43/44`, SSH `aboss`)统一配置为
`type=log, scheme=sftp, port=22, username=aboss, encoding=gbk` 的日志数据源,
归入业务系统 `TEST_SYS01` 的数据源分类 **`后台`(A5-后台)**:

```
pathTemplate: /data/aboss/log/${biz_date:YYYYMMDD}/
globTemplate: /data/aboss/log/${biz_date:YYYYMMDD}/*run_*${biz_date:YYYYMMDD}.txt
```

* `pathTemplate` 供连接测试/健康巡检列目录; `globTemplate` 供采集读取当日全部 run 文件(单次上限 256 个文件 / 单文件 64MB);
* 两者在"数据源管理 → 编辑"里是两个独立字段("路径模板" / "文件匹配 glob"), 列表优先展示真正生效的 `globTemplate`;
* 平台无任何文件名硬编码: 只配 `pathTemplate` 时只会按目录读(拿不到 run 文件), 必须显式配 `globTemplate` 才会匹配多文件(见 `internal/datasource/logfile_glob_test.go`);
* 采集执行时刻为交易日 **22:30**, `${biz_date}` = 当日 → 指向当日目录; 目录内文件缺一个不影响其他;
* 41 号服务器复用了平台既有的 `A5_run日志` 数据源(改名并归入分类), 其余 9 台新建;
* 凭据以密文入库, 列表接口恒脱敏。

### 4.1 glob 与"实际读了哪些文件"可追溯

匹配模式按 **流程 `fileGlob` > 数据源 `globTemplate` > 数据源 `pathTemplate`** 依次取值,
支持 `${biz_date:YYYYMMDD}` / `${prev_trading_day:YYYYMMDD}` 等变量渲染。本方案的 6 条流程
`fileGlob` 一律留空 —— 10 台服务器只有 host 不同、匹配模式完全相同, 模式放在数据源上避免在
流程里重复 10 份; 前端"文件 glob"输入框下方会实时回显该分类下各数据源真正生效的模式。

每次执行都会把"实际使用的 glob + 实际读取到的文件"落进执行日志(`CollectMeta.Glob/Files`):

* 流程预览弹窗"执行日志"区块 / 任务监控 `run_log` / `GET /flows/:id/preview` 的 `runLog`+`dsOk`+`dsFailed`;
* 单源形如 `glob=/data/aboss/log/20261019/*run_*20261019.txt files=4(a5_sc_mdb1_1_32_run_20261019.txt,... 等 4 个)`;
* 分类形如 `分类采集 glob=... 服务器(成功/失败/无命中)=10/0/5 文件合计=80`, 后接逐台明细(每台的文件数、前 3 个文件名、段落数、次数/用时汇总)。

## 5. section 段落聚合 + 分类采集口径

`mode=section` 配置(6 条流程共用):

```json
{
  "mode": "section",
  "startMarker": "功能号,次数,总用时,最快,最慢,平均,名称",
  "endMarker": "个服务被调用",
  "linePattern": "^\\S+ \\S+ (?P<func>\\S+)\\s+(?P<count>\\d+),\\s*(?P<total>\\d+(?:\\.\\d+)?),\\s*(?P<fastest>\\d+(?:\\.\\d+)?),\\s*(?P<slowest>\\d+(?:\\.\\d+)?),\\s*(?P<avg>\\d+(?:\\.\\d+)?)",
  "prefixes": ["DT01", "DT02", "GT01", "GT02", "JT01", "JT02"],
  "excludePrefixes": [],
  "output": "avg"
}
```

执行链路(分类下 10 台服务器):

1. 每台服务器: glob 匹配当日全部文件 → 按数据源 `encoding=gbk` 解码 → 提取起止标记间段落 → 逐行解析 → 前缀过滤 → 单服务器聚合;
2. 跨服务器合并: 次数求和 / 最快取最小 / 最慢取最大 / 平均 = **Σ总用时 / Σ次数**(调用次数加权; 无总用字段时回退 Σ(平均×次数)/Σ次数);
3. 输出单一汇总值 → 清洗(类型转换 + 毫秒→秒线性换算) → 落库 → 判定;
4. 容错: 单台服务器读取失败或当日无匹配文件 → 不中断整体, 记入 `dsFailed` 与 runLog, 该服务器健康标记 error; 全部失败才判定采集失败; 某台无命中前缀功能号 → 该台按 0 参与(不计失败); 全部服务器都无命中 → 采集失败(值为缺失而非 0)。

前缀归并规则(与指标树一致, 仅 2 类):

| 类别 | 指标前缀 | 规则 |
| --- | --- | --- |
| 后台交易请求 | `A5_JIAOYIQINGQIU*` | 功能号以 `DT01`/`DT02`/`GT01`/`GT02`/`JT01`/`JT02` 开头(现货/两融/期权的委托与撤单) |
| 后台非交易请求 | `A5_FEIJIAOYIQINGQIU*` | 排除以上 6 个前缀的其余全部功能号(查询类/消息类/清算类/系统类) |

单位换算: 日志耗时单位为**毫秒**, 指标单位为**秒** → 清洗链 `linear(a=0.001)`(笔数不做换算)。

## 9. 风险与注意

* **SFTP 安全**: MVP 为密码认证 + 跳过 HostKey 校验(平台既有行为); 生产建议 known_hosts/密钥认证;
* **并发**: 6 条流程 × 10 台服务器, 单次约 11s(受 `collect_concurrency` 全局并发保护), 交易日 22:30 集中执行分钟级完成;
* **口径确认**: 实测交易类委托功能号仅出现在 32/33 号节点; 若业务上"交易请求"还应包含其他前缀(如 `DT06`、`DQ..`), 只需改流程 `prefixes`/`excludePrefixes`(配置级, 无需改代码);
* **文件缺失**: 某台服务器当日无某服务统计段落 → 该台跳过(记 runLog), 不污染加权平均; 全部缺失 → 值缺失并触发平台"缺数"预警;
* **编码/格式**: 数据源 `encoding=gbk` 必填; A5 若升级为 UTF-8 输出, 改数据源配置即可; 日志出现新功能号形态无需改正则(功能号取第 3 个非空字段)。

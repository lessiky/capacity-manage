## 1. 版本与发布说明

### 1.1 版本号规范

- 格式：`vX.Y.Z`（X 重大/一期=1，Y 功能发布，Z 修复）；
- 镜像 tag 与版本号一致：`capacity-manage/backend:v1.0.0`、`capacity-manage/frontend:v1.0.0`；
- compose 通过 `IMAGE_TAG` 变量引用；dev 环境固定 `dev` tag。

### 1.2 二期发布说明（v2.0.0）

**范围**

- 告警累积升级、SMTP/IM/Webhook、模板、订阅、静默、数据质量和历史补采；
- 报表中心、日报预测列、级别变化、统计预测、风险清单和报表订阅；
- AI 受限修正、事件因子、开放 API、请求签名、归档和二期扩展项；
- 容器级沙箱加固、操作/API/AI 审计和数据权限回归。

**技术证据**

- `e2e_m6.py`、`e2e_m7.py`、`e2e_m8.py` 全部 `ALL ... CHECKS PASSED`；
- `testing/security/sec_test.py` 51/51 PASS；
- 后端/前端构建、静态检查和单元测试在 M8 收口轮次通过；
- 预测回测和页面截图见 `docs/40-test/预测回测报告.md` 与 `output/playwright/m8-*.png`。

**发布门禁**

| 门禁 | 状态 |
| --- | --- |
| M6/M7/M8 功能自动化 | 通过 |
| 安全 | 通过（51/51） |
| 50,000 指标预测性能 | **未执行**，必须在生产等价硬件复测 |

### 1.3 一期历史版本

**范围（P0/P1 需求全量）**
- 基础平台：登录/RBAC（功能权限 + 数据权限）、操作日志、热配置参数；
- 业务系统/交易日/指标（三级阈值，百分比 + 绝对值）；
- 三类采集：SQL / 日志解析 / Python 沙箱脚本（版本管理、预览试跑、调度、重试、超时、执行日志）；
- 数据落地：日内数据点（90 天分区保留）+ 日汇总（水位/三级判定）+ 手工修正留痕；
- 告警闭环：生成/合并/认领/处理/关闭/SLA，数据异常（P2）告警；
- 报表：日报自动生成（00:30）+ Excel/PDF 导出（数据权限）；
- 大盘：总览 KPI/TOP10/30 天趋势、系统视图、指标详情趋势；
- AI 辅助（可插拔）：流程配置草稿、清洗脚本生成 + 试跑、配置助手；调用审计全量留痕、送模脱敏；
- 平台自检（基础版）。

**质量结论（详见 40-test 报告）**
- 集成 E2E（e2e_m5）：全链路 ALL PASSED；
- 安全测试：40/40 通过，无高危漏洞（安全测试报告）；
- 性能测试：S1-S8 达标（性能测试报告），5 万指标容量基线已记录；
- 缺陷：P0/P1 清零；P2 遗留见缺陷统计报告（均附规避方案）。

**已知限制（一期边界，二期解决）**
- 告警仅平台内展示（无邮件/IM 推送、无升级/防抖/静默窗口）；
- 日汇总为逐指标 upsert，超大规模（>1 万指标）日汇总耗时线性增长（P2 改造项）；
- 沙箱为 OS 级限制（MVP），gVisor/容器级隔离为二期加固；
- 单节点部署（进程自愈 + 每日备份），双活为目标形态。

## 2. 发布方式（版本号 + 发布说明 + 回滚预案）

1. **版本化**：tag `v2.0.0` → 构建镜像（backend/frontend）→ 镜像仓库推送（tag 不可变）；
2. **迁移脚本版本化**：数据库迁移随镜像内 migrate 命令执行（幂等），`db/` 目录纳入版本管理；
3. **旧版本镜像保留**：上一版本 tag 保留 ≥2 个发布周期，供回滚；
4. **数据回滚脚本**：备份恢复流程见《运维手册》§3/§5.2；破坏性迁移必须附对应数据回滚脚本并演练；
5. **发布检查单**（§3）逐项签核后方可执行。

## 5. 发布日操作手册（摘要）

```
# 1. 构建与推送（CI 或手工）
docker compose -f deploy/docker-compose.yml --env-file deploy/env/uat.env build backend frontend
docker tag ... && docker push ...   # tag = v2.0.0

# 2. 目标环境切换版本
IMAGE_TAG=v2.0.0 docker compose -f deploy/docker-compose.yml --env-file deploy/env/uat.env up -d

# 3. 验证
#    - 平台自检页全绿
#    - 冒烟 5 步（检查单 #9）并执行二期专项检查 #11~#18
#    - 观察 30 分钟（任务成功率/5xx/日志）

# 4. 回滚（如需）
IMAGE_TAG=v<上一版本> docker compose ... up -d   # + 数据回滚（如迁移含破坏性变更）
```

## 6. 验收组织（计划 §9 末节）

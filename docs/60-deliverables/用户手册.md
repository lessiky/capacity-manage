# 容量管理平台用户手册（二期）

| 项 | 内容 |
| --- | --- |
| 版本 | V2.0（2026-10-22，对应二期 R2.1~R2.3） |
| 适用读者 | 平台管理员、系统管理员（业务侧配置人员）、数据查看用户 |
| 界面入口 | 浏览器访问平台地址（如 `http://<host>:80`），账号由管理员在"系统管理"中开通 |

## 1. 角色与权限

| 角色 | 主要能力 | 数据范围 |
| --- | --- | --- |
| 平台管理员（platform_admin） | 全部功能：基础配置、告警策略/通知、报表/预测、事件因子、开放 API、归档和系统管理 | 全部系统 |
| 系统管理员 | 系统建档、指标/数据源/流程/脚本配置、告警策略与处理、报表和预测查看 | 被授权的业务系统 |
| 数据用户 | 大盘、系统视图、指标趋势、预测风险、数据查询、报表查看/导出、告警认领 | 被授权的业务系统 |

- 数据权限按"用户 → 业务系统 → 权限级别（view/manage）"配置（系统管理 → 数据权限），未授权系统的数据、指标、告警、流程、任务一律不可见（越权访问返回 403）。
- 会话有效期 2 小时（可配），空闲滑动续期；连续 5 次登录失败锁定 15 分钟。

## 2. 首页（总览大盘）

- KPI 卡：系统数 / 指标数（活动指标数）/ 当日新增告警 / 活动告警 / 当日采集失败；
- 状态分布环图：正常 / 预警 / 危险 / 缺数 指标数；
- TOP10 高水位指标：点击任一项进入指标详情；
- 30 天平台水位趋势（日平均 / 日最高）。

## 3. 业务系统

- 系统建档：编码（唯一）、名称、部门、负责人、级别（core/general）、状态；core 级系统用于重点保障标识；
- 系统视图（菜单"系统视图"）：从大盘 TOP10 或系统列表进入，展示系统内全部指标的当前值、水位条、三级阈值与状态色块，点击下钻指标详情。

## 4. 指标管理

- 字段：指标编码（全局唯一）、名称（系统内唯一）、类别、指标类型（usage/absolute/increment）、单位、统计口径（latest/max/min/avg/sum）、判定方向（越高越差/越低越差）；
- 三级阈值：基线值 + 预警线 + 危险线；支持两种表达方式——**百分比**（相对基线的占比）与**绝对值**（与单位一致）；
- 指标详情：当前值/水位、90 天趋势（含三级参考线、超线区间着色、缺数日期标记）、日内数据点、修正历史；
- 停用/删除：活动流程引用中的指标需先停用流程；存在历史日数据的指标不可删除（保持停用）。

## 5. 数据源

- 类型：数据库（db）/ 日志（log，本地路径或 SFTP）；
- 建库连接：驱动、主机、端口、库名、账号；**密码加密存储（AES-256-GCM）**，页面与日志全程脱敏（`******`）；
- "连接测试"按钮：创建后自动测试一次，可随时重测；健康状态与连续失败次数在列表可见；
- 采集账号只读要求：由运维在源系统侧配置（上线检查单核查项）。

## 6. 采集流程

一个流程 = 一个指标的采集定义（一流程对一指标）。

- 采集类型：**SQL**（参数化查询模板，变量 `${biz_date}/${prev_trading_day}/${system_code}/${hour}` 等）、**日志解析**（正则/分隔规则提取数值，支持 MB→GB 等单位换算）、**Python 采集**（引用"脚本管理"中的激活版本，运行于平台沙箱，不访问数据源、不连接任何目标机，因此流程无需绑定数据源）、**脚本采集**（脚本与参数下发到执行目标主机临时目录运行，支持 Python/Bash/PowerShell，Linux 与 Windows 同规则，须绑定 ssh 执行目标）；
- 调度模式：普通 cron（`分 时 日 月 周`）/ 交易日模式（选市场，自动定位下一交易日及收市后窗口）；
- 流程操作：创建 → 编辑 → **预览试跑**（不落地，查看解析/清洗结果）→ 激活/停用；激活后按调度自动执行；
- 重试与超时：失败自动重试（参数可配），超时任务强制终止并记录；
- AI 辅助（可选）：对话框"AI 生成配置"输入自然语言 → 生成流程草稿 JSON → **人工审核后**应用到表单（不自动保存）；
- 流程级隔离：单流程失败/超时不影响其他流程。

## 7. 脚本管理

- 脚本用途：collect（采集）/ clean（清洗）；**语言**：Python / Bash / PowerShell（Python 可跑本地沙箱，Bash/PowerShell 仅随"脚本采集"下发到执行目标）；
  - 版本管理：可维护多版本，"激活"切换生效版本，支持回滚到历史版本；**保存版本前的语法校验只对 Python 生效**（走沙箱校验器），Bash/PowerShell 由目标机解释器执行、保存时不做本地校验（正确性以目标机执行结果与执行日志为准）；
- 本地沙箱约束（Python 采集/清洗）：仅白名单模块（json/math/re/datetime/decimal/collections 等）；无网络；仅工作目录可写；超时默认 5 分钟强制终止；CPU/内存受限；
- 本地沙箱约定：入参经环境变量 `CAP_PARAMS`（JSON，含 `${biz_date}` 等替换后的值）、`CAP_INPUT`（JSON 样例/原始数据）；输出 stdout 最后一行 JSON 数组 `[{"value": 数值, "unit": "单位"}]`；
  - 脚本采集（远程执行）约定：先在"数据源"中登记**执行目标**（类型 ssh，填主机/端口/账号/OS/临时目录），流程采集方式选"脚本采集"并绑定该执行目标；脚本与 `params.json` 由平台下发到目标机临时目录，执行结束后自动删除；脚本从同目录 `params.json` 读入参（平台内置变量 + 流程配置的自定义参数），stdout 最后一行输出 **JSON 数组**；脚本不要依赖工作目录（远端执行不 `cd` 到临时目录），须用脚本自身路径定位 `params.json`；Windows 的 `.ps1` 请保持纯 ASCII（Windows PowerShell 5.1 按 ANSI 读取无 BOM 文件，中文注释可能导致解析失败）；
  - 参考脚本（获取指定磁盘空间利用率）：Linux/Bash `backend/worker/examples/collect_disk_linux.sh`（入参 `mount`，默认 `/`）、Windows/PowerShell `backend/worker/examples/collect_disk_windows.ps1`（入参 `drive`，默认 `C:`）、Python 通用版 `backend/worker/examples/collect_disk_remote.py`；
  - 参考脚本的指标名取法：`metric` 入参 > 平台内置 `metric_code`（当前流程绑定的指标）> 脚本默认值。**入参 `metric` 留空即自动跟随流程指标**，同一脚本可复用到不同设备/不同指标的流程，不必改脚本；确需固定名字时再显式配 `metric`；
- AI 生成清洗脚本：输入样例 + 需求 → 生成脚本 → **试跑对比**（输入/输出前后对照）→ 保存为新版本。

## 8. 任务监控

- 按流程/指标/状态/日期过滤采集任务；
- 状态：running / success / failed / timeout；
- 执行日志：脚本 stdout/stderr 尾部、耗时、错误类型；失败任务可手工"重跑"（触发）。

## 9. 告警中心

- 三级判定生成告警：normal / warn（预警）/ danger（危险）；同指标同级别恢复前仅保留一条活动告警（后续超线仅刷新记录，不重复生成）；
- 状态机：活动 → 处理中（认领）→ 已恢复 / 已关闭；关闭后仅可追加备注；
- SLA：按级别统计响应/处理时长，超时未处理在看板标红；
- 数据异常（P2）：采集失败/缺数/异常值占比超限由采集侧独立产生告警。

## 10. 报表中心

- 按业务日查看日报：指标列表（当前值/水位/状态）+ 超线清单（危险优先）/ 缺数清单 / 采集异常清单 + KPI；
- 日报自动生成：每日 00:30（参数可配，在日汇总之后）；可手工"重新生成"（幂等）；
- 导出：Excel（数据明细）与 PDF（图文版式，含图表）；导出遵循数据权限（仅导出授权系统）；
- 已生成日报列表：按日下载。

## 11. 数据管理

- 日内数据点（RT）查询：按指标/时间范围，展示采集点（含原始值/清洗值/异常标记/判定级别）；
- 日数据查询：按指标/业务日范围，展示汇总值与水位；
- 质量评分：按指标/日期范围查看质量分与完整性、及时性、异常率、重复率等维度，列表分页展示（默认 100 条/页，可切换 50/100/200/500）；
- 手工修正：对日数据的 `stat_value` / `water_level` 修正，**强制填写原因**，保留原值快照与操作人（可追溯、可还原）；
- 清洗轨迹：日内数据的 cleaningTraces 展示清洗规则命中过程。

## 12. 交易日

- 交易日历维护（多市场：沪/深/境外），导入当年 + 次年日历；
- 推导服务："前/后第 N 个交易日"在配置与报表中统一使用（`${prev_trading_day}` 等变量）。

## 13. 系统管理（平台管理员）

- 用户管理：创建/停用、重置密码、分配角色；
- 角色管理：内置角色 + 自定义角色（权限点勾选）；
- 数据权限：为用户/角色授权业务系统及级别；
- 参数管理：登录策略（失败锁定次数/时长）、日报时间、调度并发、沙箱超时等热配置（修改后免重启生效）；
- 操作日志：关键操作留痕（对象/操作人/时间/摘要），凭据脱敏；
- AI 调用日志：AI 功能调用审计（功能/用户/状态/耗时/输入输出摘要，摘要脱敏）；
- 平台自检：backend/worker/存储/调度/数据源健康一览（FR-ADM-08 基础版）。

## 14. 告警策略与通知订阅（二期）

### 14.1 累积升级策略

- 首次命中阈值创建 P3；数据质量类告警为 P4；级别顺序为 `P1 > P2 > P3 > P4`；
- 预警线可配置“连续 N 天”或“最近 N 天中 M 天”升级 P2；
- 危险线可配置“连续 N 天”或“最近 N 天中 M 天”升级 P1；
- 同一业务日多次超线只计一次命中日；缺数中断连续规则，但不单独中断窗口规则；
- 策略支持全局、业务系统、指标作用域；多选作用域按“任一命中”生效；
- 页面“模拟/预览”可按指标、日期窗口重放，不写库、不修改活动告警。

### 14.2 通知渠道、模板和订阅

- 渠道：SMTP、企业微信、钉钉、飞书、通用 Webhook；
- 模板：告警、恢复、升级、报表；变量由模板预览校验；
- 订阅：按作用域、级别、告警类型、收件人、渠道、静默时段和去重窗口配置；
- 同一告警同一级别在去重窗口内只发一次，升级后允许再次通知；
- 失败按 1/5/30 分钟退避重试，连续失败生成渠道异常 P4 告警；
- 通知日志可查看渠道、目标、状态、尝试次数、错误摘要，并支持手工重试。

### 14.3 静默

支持指标级、系统维护和全局维护窗口。静默期间告警和通知日志仍完整留存，只抑制外发并记录原因。

## 15. 报表中心（二期）

- 日报：保留一期内容，并增加预测列和级别变化章节；
- 周报/月报：环比、同比、增长率、增长最快 TOP、超线变化；
- 容量使用分析：水位 TOP N、部门/分类分布、超线率、告警频次；
- 容量预测报表：预警/危险 ETA、置信区间、风险分、数据质量、模型类型与解释；
- 告警汇总：数量、MTTA、MTTR、高频指标、未闭环和升级次数；
- 报表模板支持预览、生成、Excel/PDF 下载、运行历史和订阅推送；
- 模板、预览、导出和订阅推送均按当前用户数据权限取数。

## 16. 预测风险与事件因子（二期）

### 16.1 预测风险

- 按未来 7/14/30/60/90 天查看风险清单，支持按风险分、ETA 和水位筛选、排序、CSV 导出和下钻；
- 风险窗口不大于 30 天时优先使用 30 天预测，大于 30 天时优先使用 90 天预测；首选时窗不可用时自动回退另一时窗；
- 指标详情叠加预测曲线、95% 置信区间、预警/危险 ETA 和风险评分；
- 数据不足、质量不足或趋势方向不符时显示明确状态，不输出伪 ETA；
- 管理员可手工重新计算预测批次；选择“部分指标或系统”后，可按业务日期、系统和指标组合限定重算范围，未选中的指标结果保持不变；
- 风险清单的 AI 列显示修正状态，展开行可查看模型、耗时、调整幅度、理由/错误以及 AI 建议 ETA；
- 指标详情工具栏可用“容量预测”开关隐藏预测详情卡，可用“预测线”开关隐藏趋势图上的预测虚线和置信区间；两个开关的选择会保存在当前浏览器中。

### 16.2 AI 修正

- 先执行统计预测，AI 只对统计结果做受限修正；
- AI 成功率、解释、耗时、事件版本、统计前后曲线可在指标详情对比；
- AI 关闭、认证失败、超时、非法 JSON 或调整超幅时自动降级，统计预测仍可用；
- 超幅 AI ETA 只作建议展示，不替代风险清单和报表的统计主 ETA。

### 16.3 事件因子

- 事件类型：上线、迁移、业务高峰、维护、政策变化、其他；
- 作用域：全局、业务系统、指标；
- 事件默认草稿，必须人工确认后才进入预测；
- 修改事件会生成新版本，历史版本可追溯；过期事件不再进入模型；
- “AI 建议”只给出影响方向、幅度、置信度和解释，需人工确认后生效。

## 17. 开放 API（平台管理员配置）

开放 API 用于向第三方或数据平台提供容量数据，不占用登录会话。

### 17.1 Scope

| scope | 用途 |
| --- | --- |
| `data:read` | 查询日内和日数据 |
| `forecast:read` | 查询最新预测结果 |
| `alert:webhook` | 告警 Webhook 预留范围 |

### 17.2 Key 管理

- Key 格式为 `{keyId}.{secret}`，secret 只在创建或轮换时显示一次；
- 可配置系统范围、每分钟限流、过期时间和请求签名；
- 停用后立即拒绝，重新启用后可恢复；停用状态可永久删除；轮换 secret 后旧 secret 立即失效；
- “调用审计”保留成功和拒绝记录，可按成功/拒绝筛选；API Key 与调用审计列表均分页展示（默认 20 条/页）。

### 17.3 请求签名

开启签名后，调用方携带 `X-API-Key`、`X-Cap-Timestamp`、`X-Cap-Nonce`、`X-Cap-Signature`：

```text
canonical = timestamp + "\n" + nonce + "\n" + METHOD + "\n"
          + path + "\n" + rawQuery + "\n" + sha256(body)
signature = hex(HMAC-SHA256(secret, canonical))
```

时间戳超窗、nonce 重放、签名错误均返回 401。

### 17.4 数据接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/open/stream/day` | 日数据，默认最近 90 天 |
| `GET /api/v1/open/stream/rt` | 日内数据，默认最近 24 小时 |
| `GET /api/v1/open/forecast` | 最新预测批次，horizon=30/90 |

## 18. 保留与归档（系统管理）和扩展项

- “保留与归档”位于**系统管理**菜单，可配置日内在线保留天数（默认 90）和日数据在线天数（默认 1095）；
- 归档记录列表分页展示（默认 20 条/页），支持查看在线/已下线状态与按需恢复；
- 系统每日按配置自动执行“归档并下线”：超期完整月分区先压缩归档，归档成功后再从在线库下线，数据只保留在归档文件里；
- 归档按完整月分区压缩，支持运行历史、成功/失败状态、在线/已下线状态和按指标+日期查询；
- 已下线的归档可点“恢复”回填到在线库（重复恢复不会产生重复数据），恢复后下次归档会重新压缩再下线；
- 归档任务幂等，已经成功的分区不会重复计入；
- 指标管理新增“衍生指标”“阈值模板”“批量导入”标签页；衍生指标可停用、重新启用，并在停用后删除，列表分页展示（默认 20 条/页）；
- 阈值模板可停用、重新启用，并在停用后删除；停用模板不可再套用到指标；
- 批量导入记录分页展示（默认 20 条/页），导入完成后回到第一页；
- 交易日新增“完整性检查”标签页。

## 19. 数据质量与历史补采

- 质量维度：完整性、及时性、异常值占比、重复值、缺失天数、数据新鲜度；
- 质量分低于 0.8 时预测标记 `insufficient_quality`，不输出确定性 ETA；
- 历史补采支持按流程和日期区间执行，完成后自动重算日汇总、质量分、告警重放和报表缓存；
- 同一业务日重复补采幂等，不重复膨胀数据点。

## 20. 常见问题

| 问题 | 处理 |
| --- | --- |
| 登录被拒"账号已锁定" | 连续失败触发锁定，等待 15 分钟（或管理员在参数中调整），勿反复尝试 |
| 采集任务 failed | 任务监控查看执行日志：SQL 错误/日志格式不匹配/脚本异常；修正配置后重跑 |
| 指标显示"缺数" | 当日应采未采：检查流程是否激活、数据源健康、任务日志；确认无法恢复时手工修正并留痕 |
| 日报未生成 | 检查 `daily_report_time` 参数与平台自检；报表页手工"重新生成" |
| 看不到某系统 | 联系管理员确认数据权限授权 |
| AI 生成内容如何使用 | AI 输出仅为草稿/参考：流程配置须人工审核+预览试跑后保存；脚本须试跑对比后作为新版本保存 |
| 预测显示“AI 已降级” | 查看降级原因；统计预测仍为主结果，修复 AI 配置后重新计算 |
| 事件已保存但未影响预测 | 检查事件是否为“已确认”、是否在预测窗口内、是否已过期 |
| 开放 API 返回 401/403/429 | 401 检查 secret/签名/时间戳/nonce；403 检查 scope、Key 状态和系统范围；429 检查每分钟限流 |
| 归档查询为空 | 确认日期已超过在线保留期、归档运行成功且指标属于该分区 |
| 质量不足无法预测 | 在数据管理中补采或修正缺数/异常数据，重新执行质量检查和预测 |

# 容量管理平台二期开发计划（告警累积升级 + 预测前移）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 20 周内完成二期交付，补齐告警外发与闭环，支持按连续天数或最近窗口累计触发次数进行 P3→P2/P1 升级，并把常规预测、容量预测报表、AI 辅助预测和事件因子能力全部纳入二期。

**Architecture:** 告警侧采用“单点阈值事件 + 日级命中状态 + 可配置升级策略 + 单一活动告警更新”的架构，告警级别变更不新建重复告警。预测侧采用“确定性统计模型为基线、AI 仅做受约束修正和解释、AI 不可用时自动回退统计预测”的双层架构。报表中心统一承载日报、周报、月报、容量分析、预测和告警汇总。

**Tech Stack:** Go（Gin + GORM）、PostgreSQL 16、Redis 7、Vue 3 + Element Plus、Python 3.11、现有 OpenAI 兼容 LLM 适配器、现有 SMTP/IM 可插拔通知扩展点。

**Spec:** `docs/容量管理平台需求文档.md`、`docs/00-baseline/需求基线-V1.0.md`、用户 2026-10-20 二期范围指令。

## Global Constraints

- 二期必达需求：`FR-MON-11/15/20/21/22/30/31/32/33`、`FR-AI-05/06`、`FR-RPT-02/03/04/05/10/13`、`FR-DAY-04/06/07`、`FR-COL-16/23/35`、`FR-MET-04/05/13`、`FR-SYS-06`、`FR-TD-05/06`。
- 范围变更：`FR-AI-05`、`FR-AI-06`、`FR-MON-33` 从原三期前移到二期；容量预测、AI 辅助预测和预测报表必须纳入二期验收。
- 新增需求：`FR-MON-16 阈值累积升级`。默认命中阈值先产生 P3，预警线命中满足规则后升级 P2，危险线命中满足规则后升级 P1。
- 级别顺序固定为 `P1 > P2 > P3 > P4`。容量阈值类告警使用 P1/P2/P3；采集失败、缺数、异常值等数据质量类默认 P4，可按系统覆盖。
- 同指标同一活动周期仅允许一条阈值告警。升级时更新原告警的当前级别、升级时间、证据窗口和 SLA，不关闭后再创建重复活动告警。
- 阈值累积升级和超时升级是两条独立规则：前者改变告警级别，后者改变通知对象和处置路径，两者可同时生效。
- 统计预测必须先于 AI 修正完成；AI 服务不可用、超时、输出非法时，预测任务仍生成统计预测结果并记录降级。
- AI 只能对统计预测施加受限修正：斜率倍率 `0.75~1.25`、截距调整 `-20%~20%`、置信度调整 `-0.20~0.20`。越界结果丢弃并回退统计预测。
- 事件因子只有状态为 `confirmed` 且经人工确认后才参与预测；AI 只能提出建议。
- 所有预测结果必须可复现：保存模型版本、训练窗口、数据截止日、数据质量、事件因子版本和输入摘要。
- 所有报表和 API 继续执行系统级数据权限；通知、导出、预测事件和 AI 调用均审计。
- AI 输入继续经过 `masking.SanitizeForAI`，禁止把凭据、连接串、手机号、身份证和银行卡号送入模型。

## 3. 告警累积升级设计

### 3.1 规则定义

新增需求 `FR-MON-16` 定义两类升级规则：

1. 预警线累计升级：同一指标连续 N 天命中预警线，或最近 N 天内有 M 天命中预警线，当前告警升级为 P2。
2. 危险线累计升级：同一指标连续 N 天命中危险线，或最近 N 天内有 M 天命中危险线，当前告警升级为 P1。

默认策略：

| 目标级别 | 来源阈值 | 连续条件 | 窗口条件 | 日口径 |
| --- | --- | --- | --- | --- |
| P2 | 预警线 | 连续 3 天 | 最近 7 天内有 3 天 | 自然日 |
| P1 | 危险线 | 连续 2 天 | 最近 5 天内有 2 天 | 自然日 |

计算规则：

- 当天命中的定义按指标 `judge_direction` 决定：`higher_worse` 为 `value >= line`，`lower_worse` 为 `value <= line`。
- 危险线命中日同时计为预警线命中日。
- 同一业务日多次采集只计一次命中，不能因日内 100 次超线直接满足“3 天”规则。
- 连续条件为包含当天的最近 `N` 个日期全部命中；中间出现未命中、缺数或异常日则从下一个命中日重新起算。
- 窗口条件为包含当天的最近 `N` 个日期内，命中日数量大于等于 `M`；缺数和异常日不命中，但不单独中断窗口。
- 多个规则同时满足时取目标级别最高的规则。危险线 P1 规则优先于预警线 P2 规则。
- 当天首次触发且没有活动告警时，先创建 P3。日汇总或数据修正后满足 P2/P1 规则时，在原告警上升级。
- 数据修正或历史补采会重放受影响指标的最近最大窗口。重放结果高于当前级别时升级；低于当前级别时写入级别变更历史，默认不自动降级，必须由管理员确认。
- 指标连续 `recover_days` 天低于预警线后，告警恢复。默认 `recover_days=2`，恢复后下一次重新触发从 P3 开始。

### 3.3 核心算法

新增 `backend/internal/alert/escalation.go`，纯函数先实现并单测：

```go
type DailyHit struct {
    BizDate   time.Time
    WarnHit   bool
    DangerHit bool
    DataState string // valid/missing/anomaly
}

type EscalationPolicy struct {
    ID              int64
    SourceLine      string // warn/danger
    TargetLevel     string // p2/p1
    Mode            string // consecutive/window_count
    ConsecutiveDays int
    WindowDays      int
    HitDays         int
}

type EscalationDecision struct {
    Level    string
    Matched  bool
    PolicyID int64
    Evidence map[string]any
    Reason   string
}

func EvaluateEscalation(policies []EscalationPolicy, hits []DailyHit) EscalationDecision
```

确定性规则：

```text
连续模式:
  取包含当前日期的最近 consecutive_days 个日期
  全部日期 source_line 命中且 data_state=valid -> matched

窗口模式:
  取包含当前日期的最近 window_days 个日期
  其中 source_line 命中日数量 >= hit_days -> matched

最终:
  在所有 matched 策略中选择 target_level 数值最小者
  没有任何 matched 策略时保持当前级别；首次触发时使用 P3
```

### 3.4 判定接入点

| 时点 | 行为 |
| --- | --- |
| 每次采集成功后 | 调用现有 `judge.Evaluate`；首次超线创建 P3；刷新活动告警最近值；同一业务日只更新 `alert_daily_hit`，不重复累计 |
| 每日汇总后 | 对当日涉及指标重算 `alert_daily_hit`，调用 `EvaluateEscalation`，升级原活动告警 |
| 手工修正后 | 对修正指标最近最大 `window_days` 执行重放；高则升级，低则记录 `pending_downgrade` 证据 |
| 历史补采后 | 与手工修正相同；补采完成事件驱动，不依赖人工刷新 |
| 策略变更后 | 写操作审计并主动失效缓存；从下一次判定开始生效，不回写历史告警 |

### 3.5 告警更新与通知

`backend/internal/alert/service.go` 的 P0/P1 硬编码删除，改为：

1. 首次触发：创建 `level=p3`，记录 `source_line` 和触发阈值。
2. 升级：更新原 `alert_record.level`、`escalated_at`、`deadline_at`、`escalation_count`、`evidence_window`。
3. 写入 `alert_level_history`：从旧级别到新级别，附规则编号、窗口日期和命中天数。
4. 发送一条“级别升级”通知，不创建新告警编号。
5. 正常刷新不重复发送通知。
6. 处理时间线新增 `escalate` 节点，详情页展示升级依据。

### 3.6 验收场景

- 当天第一次超过预警线只产生 P3。
- 同一日重复超线 100 次仍只计 1 个命中日。
- 连续 3 个自然日超预警线，告警从 P3 升级为 P2，并产生一条升级通知。
- 最近 7 天内有 3 天超预警线，同样升级为 P2。
- 连续 2 天超危险线，告警从 P3 或 P2 升级为 P1。
- 连续序列中出现缺数日时，连续规则中断，窗口规则仍可按其他命中日计数。
- 修正某天日数据后可触发重放升级；修正导致不再满足规则时只记录降级建议，不自动降级。
- 策略从 P3→P2 修改为连续 5 天后，下一次判定立即使用新阈值，无需重启。
- 超时升级不改变告警级别，只追加通知对象和升级轨迹。

### 4.2 订阅与模板

### 6.2 统计预测

新增 `backend/internal/forecast/engine.go`，提供纯函数：

```go
type Point struct {
    BizDate time.Time
    Value   float64
}

type Series struct {
    MetricCode     string
    JudgeDirection string
    WarnLine       *float64
    DangerLine     *float64
    Points         []Point
    QualityScore   float64
}

type ForecastResult struct {
    Status        string
    ETAWarnDate   *time.Time
    ETADangerDate *time.Time
    Slope         float64
    Intercept     float64
    ResidualStd   float64
    Confidence    float64
    Curve         []CurvePoint
    RiskScore     float64
    Explanation   string
}

func ForecastLinear(series Series, horizonDays int) ForecastResult
func ForecastGrowth(series Series, horizonDays int) ForecastResult
func SelectBestModel(candidates []ForecastResult, historicalError map[string]float64) ForecastResult
```

实现要求：

- 使用 30 天和 90 天两个训练窗口，输出两个 horizon。
- 线性模型：最小二乘拟合 `y = a + b*x`，ETA 为预测曲线第一次越过阈值的最早日期。
- 增长率模型：使用最近 7 天和 30 天增长率估计未来值，适合单调增长的使用率类指标。
- 回测：留出最近 7 天或 14 天，按 MAE/MAPE 选择模型；没有回测数据时默认线性。
- 数据门槛：30 天窗口至少 14 个有效点，90 天窗口至少 30 个有效点，质量分低于 0.8 不产出 ETA。
- 置信区间：以残差标准差计算 95% 区间，并对低于 0 的容量值截断到 0。
- 趋势方向与阈值方向不一致时返回 `never`，例如 `higher_worse` 且斜率不为正。
- 风险评分固定为可复现公式：`0.40*到线紧迫度 + 0.30*趋势强度 + 0.20*模型置信度 + 0.10*数据质量`，再乘事件调整系数。

| 预测批次性能 | 50,000 指标、30/90 天双窗口在 30 分钟内完成 |

| 可复现 | 相同输入、模型版本、事件版本重复执行产生相同数值结果 |

## 8. 测试策略

### 8.1 告警规则

- 使用固定时间线和固定策略做表驱动测试，不依赖系统当前时间。
- 每条规则必须覆盖命中、未命中、边界命中、缺数、异常、同日多次、连续中断和窗口跨月。
- 使用历史告警数据重放，确认迁移前后级别映射正确。
- M6 前完成一次真实 IM 和邮件演练。

### 8.2 预测

- 引擎纯函数与数据库服务分层测试。
- 对每个试点指标保留最近 14 天作为回测集。
- 同时跑线性、增长率和 AI 修正三种结果，报表展示模型选择依据。
- 将 AI 服务故障注入纳入 E2E，不允许 AI 故障阻塞日汇总和统计预测。

### 8.3 报表与通知

- Excel 校验数据页、图表页和权限范围。
- PDF 通过页面渲染和文本抽取双重校验。
- 通知模板校验变量替换、转义、长度截断和链接可达性。
- 订阅推送重复执行必须幂等。

### 8.4 性能与安全

| 场景 | 目标 |
| --- | --- |
| 50,000 指标预测 | 30 分钟内完成 30/90 天双窗口 |
| 预测查询 API | p95 小于 3 秒 |
| 风险清单首屏 | p95 小于 3 秒 |
| 报表生成 | 20,000 指标报表小于 60 秒 |
| 通知突发 | 1,000 条告警在 5 分钟内完成去重和入队 |
| 权限 | 功能权限、系统数据权限、导出和 API scope 全部不可越权 |
| 安全 | 无高危漏洞，Webhook 签名、重放保护和 AI 脱敏全部通过 |

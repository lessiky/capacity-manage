# 高可用改造评估

| 项 | 内容 |
| --- | --- |
| 版本 | V1.0（2026-10-22） |
| 评估对象 | 容量管理平台当前 Docker Compose 单节点部署 |
| 结论 | 满足当前试点与非关键时段使用；生产推广前应完成数据库、缓存、入口和文件存储的高可用改造 |

## 1. 当前架构

| 组件 | 当前形态 | 高可用缺口 |
| --- | --- | --- |
| frontend | 单 Nginx 容器 | 单实例故障导致页面不可用 |
| backend | 单 Go 实例，包含 API 与调度器 | 故障时 API、采集触发、日汇总、预测、报表订阅同时中断 |
| worker | 单 Python 容器 | 脚本采集与清洗任务中断；多实例需共享任务队列 |
| PostgreSQL | 单主库 + 持久卷 | 数据库故障影响全部业务 |
| Redis | 单实例 AOF | 会话、限流、nonce 和缓存中断 |
| 文件 | Docker volume，日报与归档同卷 | 主机故障时文件不可用，跨节点部署需共享存储 |
| 调度器 | 与 backend 同进程 | 多 backend 实例会重复调度，需要选主或分布式锁 |

## 2. 风险分级

| 风险 | 影响 | 建议优先级 |
| --- | --- | --- |
| PostgreSQL 单点 | 数据不可写、报表/预测/告警全部停止 | P0 |
| Redis 单点 | 登录会话普遍失效；API Key nonce/限流降级 | P0 |
| backend 单实例 | 控制面和调度链路全断 | P0 |
| 单入口 frontend | 页面不可访问 | P1 |
| worker 单实例 | 脚本采集积压 | P1 |
| 本地文件存储 | 日报、归档无法跨节点恢复 | P1 |

## 3. 推荐目标架构

### 3.1 基础高可用

- 入口部署 2 个 frontend/Ingress 实例，健康检查失败自动摘除。
- backend 拆分为 API 实例和调度器实例；至少 2 个 API 副本。
- 调度器使用 PostgreSQL advisory lock 或独立选主机制，确保同一任务只被一个实例执行。
- PostgreSQL 采用主备流复制 + 自动/半自动切换，备份保留 ≥30 天并定期恢复演练。
- Redis 采用 Sentinel 或受管高可用实例，AOF 与自动故障转移开启。
- 日报和归档改存共享对象存储或 NAS；数据库只保存文件引用和摘要。

### 3.2 容器与沙箱

- 业务容器统一设置 `no-new-privileges`、只读根文件系统、`cap_drop: ALL`、PID/内存/CPU 限额。
- Worker 在支持的主机使用 gVisor/`runsc`；同时保留模块白名单、无网络、临时目录清理和任务超时。
- gVisor 上线前需在生产等价硬件上验证兼容性、文件 IO、内存峰值、任务时延和故障隔离。

### 3.3 调度与数据一致性

- 预测、归档、日汇总和报表订阅必须幂等；重试或切换后不能重复发送通知或重复归档。
- 数据库切换后先校验迁移版本、复制延迟和业务日水位，再恢复调度。
- Redis 故障时 API Key 签名请求应 fail closed（当前实现返回不可用），普通业务 API 可临时降级为非签名模式，需通过配置显式启用。

## 4. 目标指标建议

| 指标 | 建议值 |
| --- | --- |
| API 可用性 | 月度 ≥99.9% |
| 数据库 RPO | ≤5 分钟 |
| 数据库 RTO | ≤30 分钟 |
| Redis RPO | ≤1 分钟 |
| Redis RTO | ≤10 分钟 |
| 调度重复执行 | 0 次业务副作用重复 |
| 备份恢复演练 | 上线前 1 次，之后每季度 1 次 |

## 5. 分阶段实施建议

| 阶段 | 改造 | 退出条件 |
| --- | --- | --- |
| HA-1 | 备份恢复演练、监控告警、调度幂等审计 | 完成一次按日恢复和一次全链路切换演练 |
| HA-2 | PostgreSQL 主备、Redis Sentinel、双 backend API | 主备切换 RTO/RPO 达标，调度不重复 |
| HA-3 | 对象存储、双入口、Worker 多副本和队列 | 单节点故障不影响连续采集与报表 |
| HA-4 | gVisor/生产等价沙箱、压测与混沌演练 | 功能、性能、安全门禁全部通过 |

## 6. M8 验收边界

M8 已提供容器级最小权限加固和本评估文档，但未完成 gVisor、生产等价硬件、数据库主备切换和混沌演练。因此高可用改造不是当前 M8 自动化验收的已完成项，应在生产推广前单独立项验收。

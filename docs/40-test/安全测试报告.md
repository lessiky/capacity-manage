## 1. 测试范围

按《容量管理平台开发计划》及二期测试要求，覆盖凭据脱敏、权限越权（垂直+水平数据权限）、注入（SQLi/命令/XSS/路径穿越/模板注入）、会话安全（JWT/登出/暴力锁定）、AI 调用审计，以及开放 API Key/scope、请求签名、Webhook HMAC 与幂等、SSRF 和事件因子权限。

## 3. 缺陷发现与处置（安全相关）

| 编号 | 级别 | 描述 | 状态 |
| --- | --- | --- | --- |
| DEF-002 | P1（安全） | 数据权限越权：`/data/rt`、`/data/day`、`/data/corrections`、`/metrics` 列表/详情/趋势、`/flows`、`/tasks`、`/dashboard/overview`、`/dashboard/trend` 未按 FR-ADM-03 过滤数据权限（仅 admin 视角无差异） | **已修复**：新增 `backend/internal/pkg/scope`（Systems/Apply/Contains/Forbidden），上述处理器全量接入；本报告 2.2 节 12 项水平越权用例为回归证据 |
| DEF-003 | P2（安全/可观测） | AI 调用审计丢失：LLM 返回文本含非法 UTF-8 字节（`0xe6 0x2e 0x2e`）时 `ai_call_log` 写入报 `invalid byte sequence for encoding "UTF8"`（SQLSTATE 22021）且错误被静默吞掉，审计行丢失 | **已修复**：`masking.Digest` 增加 `strings.ToValidUTF8` 归一 + rune 边界安全截断；`ai/handler.go audit()` 写库失败改为 `log.Error` 可观测。TC-SEC-040a 复测通过 |

## 4. 非漏洞判定（设计即安全）

- **TC-SEC-022a/b 路径穿越**：日报下载/导出的 `format` 参数仅用于在两个预定义对象 key（ReportKeys）/两种固定格式之间选择，文件路径完全由服务端按业务日期生成，用户输入不参与路径构造；测试断言相应调整为"仅返回固定日报文件或 404，且不含被穿越文件内容"。结论：无路径穿越漏洞。
- **TC-SEC-023a 命令注入**：脚本名作为数据存入 `python_script` 表（参数化 SQL），沙箱执行时以文件路径参数传递、经 `python -I -E sandbox.py` 启动，全程无 shell 拼接，特殊字符无执行语义。

### 1.2 准入条件（开始 2 周试运行前逐项确认）

- [ ] 集成 E2E（`e2e_m5.py`）全绿：采集→清洗→落地→判定→告警→报表全链路
- [ ] 安全测试（`testing/security/sec_test.py`）40/40 通过
- [ ] 性能测试（`testing/perf/perf_test.py`）S1-S8 达标（见性能测试报告）
- [ ] 生产源系统采集账号只读权限核查完成（上线检查单）
- [ ] 当年 + 次年交易日日历已导入并核对（沪/深市场）
- [ ] 阈值初始数据、系统建档、用户账号初始化完成
- [ ] 备份策略启用（数据库每日全量备份 + 按日恢复演练 1 次）
- [ ] 监控接入：进程/接口/磁盘/调度状态（平台自检页 + 运维监控）

## 2. 试运行计划（2 周）

### 2.1 总体安排

| 周次 | 重点 | 退出标准 |
| --- | --- | --- |
| 第 1 周 | 采集稳定性 + 数据正确性（业务侧逐日核对 3 个试点系统指标值与源系统一致性） | P0/P1 缺陷清零；无中断采集 ≥7 天（计划内停机除外） |
| 第 2 周 | 告警闭环 + 报表 + 用户操作熟练度（认领/处理/关闭、日报导出、大盘使用） | P0/P1 缺陷清零；P2 遗留 ≤5 且有规避方案；业务侧完成 UAT 签署 |

### 2.2 每日检查项（运维侧，每日 1 次，记录于试运行记录表）

| # | 检查项 | 方法 | 正常标准 |
| --- | --- | --- | --- |
| 1 | 平台自检 | `GET /admin/health`（前端 Admin 页"平台自检"） | backend/worker/storage/scheduler 均 ok |
| 2 | 调度任务 | 任务列表按流程过滤当日任务 | 当日应触发流程全部 success（失败/超时=0，或已处理） |
| 3 | 日汇总 | 日数据按业务日抽查 + `daily_summary_log` | status=success/partial，无 failed |
| 4 | 日报 | 报表页查看/导出当日日报（Excel+PDF） | 生成成功、超线/缺数清单与平台一致 |
| 5 | 告警 | 告警列表：新增/活动/关闭 | 新增告警均有认领或已在静默期；无超 SLA 未处理 |
| 6 | 数据核对（业务侧） | 抽 3~5 个指标与源系统对数 | 一致（清洗规则口径内） |
| 7 | 资源 | 磁盘/数据库容量/worker 队列 | 无持续增长异常；日表按分区滚动 |
| 8 | 备份 | 当日备份作业 | 备份成功且大小合理 |

### 2.3 缺陷收敛标准

- P0（平台不可用/数据错误落库/权限泄漏）：24 小时内修复并回归，试运行暂停至清零；
- P1（功能不可用有规避/性能不达标）：48 小时内修复；
- P2：记录入缺陷台账，UAT 结束前遗留 ≤5 且每项有规避方案；
- 每日缺陷例会（UAT 期间）：确认当日新增/处理/遗留，更新缺陷统计报告。

## 4. 回退与应急

- 平台故障：切换只读模式（停止调度 `SCHEDULER_ENABLED=false` 重启），数据源账号保持只读不受影响；
- 数据错误：以源系统为准，通过手工修正流程纠正并留痕；错误日汇总可重新触发（幂等）；
- 版本回滚：按《部署与发布手册》回滚预案执行（旧镜像保留 + 迁移脚本版本化，数据不破坏性回滚）。
